# SomeSide 0.9.0

一个可以直接运行的 2D 横版动作 Roguelike 原型：鼠标自由瞄准、两种战斗风格、局内道具叠加、三段关卡，以及玩家主机驱动的 2–4 人合作。

使用 Godot 4.7.2 / GDScript。画面与音效由程序生成，内置 Noto Sans SC 中文字体。

## 开始游戏

**双击根目录 `Play.cmd`**。这会使用项目内的便携 Godot 运行最新源码，不需要提前安装引擎。0.9 独立版本位于 `dist/v0.9.0/SomeSide.exe`，无需编辑器；发布包为 `dist/SomeSide-v0.9.0-windows-x64.zip`。以前的发布包继续保留，方便回退。

0.9 加入可变高度跳跃：短按低跳，长按保持原最高跳跃轨迹；羽翼空跳也可控制高度。A/D 或左右方向键同时按住时，后按方向优先，松开后恢复仍按住的方向。切出窗口、暂停和切换页面时清除游戏按键，避免持续移动或开火。静态场景与重复绘制、物品查询和 UI 更新也进行了性能优化。

0.8 支持简体中文和英文。首次启动按系统语言选择：中文系统使用简体中文，其余系统默认英文；设置中的语言选项可随时修改，后续启动优先使用已保存的选择。菜单、指南、道具效果与风险、交互提示、地图地标和首领名称都随之切换，合作玩家可各自选择语言。右上角以独立金色图标和较大的数字显示完整金币余额，阶段、计时与威胁另行显示。

双击 `Editor.cmd` 可打开工程。便携引擎和编辑器数据位于 `tools/runtime`，不会修改系统 PATH。如果拿到的是不含 runtime 的源码，启动脚本会下载官方 Godot，并使用官方 SHA512 清单校验下载包；首次运行需要网络。

在菜单中选择角色并开始单人游戏，或创建合作房间。搜集货币、开启宝箱、叠加道具；找到传送门，启动并完成首领战，继续进入下一关。第三关完成后结算。合作中可以救起倒下的队友，全队倒下会结束本局。

- **游侠**：100 生命，起始装备脉冲步枪与震荡手雷。
- **先锋**：145 生命，起始装备共鸣弧刃与裂地冲击。

主武器和主动装备各有一个槽位，现在各有 8 种可选内容。武器包含火焰喷流、回旋星刃、万雷权杖和恒星长矛；主动装备包含引力囚笼、哨戒炮台、天穹陨击和时序王冠。换下的旧装备掉到地上，装备交换不会重置冷却。

现有 **24 种可叠加被动遗物，加上 8 武器、8 主动装备，共 40 种物品**。初始只有一次跳跃，三张地图都按无道具、无冲刺的单跳能力设计；**跃迁羽翼**每层额外提供一次空中跳跃，用于捷径。**脆晶契约**每层增加 30% 伤害，同时把最大生命乘以 0.85，最低保留角色基础生命的 20%；获得前的提示面板和背包都会明确显示代价。

全部物品划分为普通（灰）、精良（绿）、稀有（紫）和传说（金）。高阶物品带来实际能力，例如中毒、额外穿透、暴击新星、致命伤抵挡、团队时序加速或更强的多目标攻击；稀有度名称与颜色在掉落提示、持有图标和图鉴中保持一致。

0.4 扩大三张地图，并为每关设计不同的地形路线、支路与地标；传送门位于需要攀登的平台，按 **M** 查看地图。保留较慢的初始移动、冲刺和火力，全部基础路线无需跳跃道具或冲刺。

| --- | --- | --- |
| 巨木雨林 | 7200 × 1900 | 48 / 18 |
| 折光断崖 | 5600 × 2800 | 45 / 18 |
| 双环遗迹 | 8400 × 2300 | 54 / 18 |

0.7 重绘了三关的分层背景、平台断面、植被和地标：雨林有巨木根系与荧光菌，峡谷有沉积岩层与废弃吊轮，遗迹有石构拱廊与机械环。两种角色使用更清楚的分层装甲和跑跳姿态，敌人各有独立轮廓；友方弹丸采用明亮硬芯和短尾，敌方弹丸采用醒目的外壳、暗芯与不同形状。

三关使用独立的敌人池，普通探索、战斗信标和传送门增援都遵循本关主题：

| 关卡 | 普通敌人及战斗方式 | 首领 |
| --- | --- | --- |
| 巨木雨林 | 棘背跃兽：蓄力跳扑；囊毒喷吐者：远程吐弹；孢尘夜蛾：标记落点后引爆孢子 | 孢冠母巢：扇形孢子弹与多点爆发 |
| 折光断崖 | 赤岩冲锋兽：直线冲锋；砂脊潜伏者：钻地突袭；晶翼巡猎者：三发晶体散射 | 裂岩巨像：成排地刺与重型冲锋 |
| 双环遗迹 | 棱镜哨卫：锁定射线；折跃猎手：闪现后蓄力齐射；修复导引者：有限治疗附近同伴并发射能量弹 | 寂光执政官：长射线与交叉光束 |

高威胁攻击先显示方向或落点预警，开始蓄力后锁定攻击几何，给玩家留下躲避时间；闪现敌人在到达新位置后会再次蓄力。眩晕或击杀施法者可取消其危险区。修复单位的治疗次数受总治疗量限制，不会无限延长战斗。

普通遭遇随探索新区域触发有限波次；站着、原地跳跃或在小范围内来回不会持续补充敌人。已有敌人仍会行动，主动启动传送门或战斗信标时也仍需完成事件。**难度随实际局内时间增长，包括停留时间**：新敌人的生命和攻击会逐渐加强，闲置不会积累一波待刷怪物。

生命、阶段/时间/金币与角落里的三个动作图标保持简洁。**已持有的被动道具以底部小图标常驻显示**，带数量角标和稀有度边框，最多两行；鼠标悬停即可查看完整效果，无需按键。按住 **Alt** 展开附近物品详情，松开后收起说明；副作用和换装代价始终直接显示。**Tab** 默认打开当前持有构筑，可切换遗物、武器和主动装备图鉴。

堆叠道具会强化对应攻击的视觉效果，设置中可调整特效强度。粒子、伤害数字和震动保持数量或幅度上限，避免高层构筑遮住战场。

0.6 让八种主武器使用清楚不同的手持模型，并统一鼠标瞄准、枪口和弹丸发射点，向左、向右或斜向射击都从实际枪口出发。新弹丸的尾迹按已经飞行的距离增长，刚发射时不会倒穿武器或身体。

拾取遗物也会改变角色外观：24 种遗物分别对应背部、肩部、胸部、头部、腰部或腿部饰件，合作队友同样可见。最多显示六个部位，同部位按稀有度、叠层与固定顺序选择代表；叠层对饰件大小和亮度的提升有上限。它们只影响显示，不改变碰撞体、射击方向或数值。

## 战利品与设施

被动遗物、武器、主动装备都以实体落在地上。靠近后查看图标、名称、效果、代价与替换对象，再按 **E** 拾取当前显示的那一件；走过物品不会自动拿走。多个目标重叠时按 **F** 切换，不必先拿不想要的物品。金币与治疗仍会自动收集。普通敌人的物品掉率为 3%，精英为 8%，首领保证掉落两件；随机由主机统一决定。

普通随机奖励以被动构筑为主，目标比例为 **88% 被动、7% 武器、5% 主动装备**。随机装备排除初始装备、全队正在穿戴、地面已有和未开启设施展示的装备，并优先避开近期出货；如果只因近期记录耗尽，会重新允许其中最久未出现的候选，避免整关断货。确实没有合适装备时回退到可叠加被动。三选终端至少提供两个不同被动、至多一件装备。后续关卡、首领与试炼更容易获得高阶物品。

| 设施 | 使用方式 |
| --- | --- |
| 补给箱 | 支付金币，生成一件地面战利品 |
| 三选终端 | 支付金币选择其中一个，另外两个立即锁定 |
| 生命祭坛 | 支付不会致死的生命代价，生成地面奖励 |
| 战斗信标 | 挑战该信标生成的敌人，清完这一波后才给奖励 |
| 装备仓 | 支付金币，生成一件主动装备，再按 E 换装 |

设施以地图中的独立实体呈现，设计参考《雨中冒险 2》的交互物类型与“付出代价获取奖励”的方式；SomeSide 的名称、规则组合、概率和数值单独设计。各设施的价格与风险以游戏内面板为准。

## 2–4 人合作

1. 每位玩家启动相同版本的 SomeSide。
2. 一位玩家创建房间，其余玩家输入该主机的 IP 地址加入。
3. 玩家在大厅选择角色并准备，主机开始游戏。

同一台电脑测试可使用 `127.0.0.1`；同一局域网使用主机的局域网 IPv4 地址。默认使用 **UDP 27841**。Windows 首次询问网络访问时，应允许游戏在所用的可信网络中通信。

当前支持直接地址连接，没有在线匹配、Steam 大厅或自动 NAT 穿透。异地连接需要双方可达的网络地址，例如已经配置的虚拟局域网，或主机路由器上的 UDP 端口映射。主机离开后房间结束，不进行主机迁移。

## 开发与验证

### Git 版本管理

仓库使用 `main` 分支；`v0.5.0` 标签记录首次纳入版本管理的可玩版本。源码、Godot 场景与导入设置、脚本 UID、中文字体及许可、测试和构建脚本均纳入管理。

`.godot/` 缓存、`tools/runtime/` 便携引擎、`tools/results/` 测试产物、预览截图和 `dist/` 发布包保留在本地并由 `.gitignore` 排除。克隆后的首次运行可通过 `Play.cmd` 自动下载引擎；导出及重新生成发布包使用下方命令。构建报告中的运行证据路径指向本地测试产物。

日常修改后使用 `git status` 和 `git diff` 检查，再用 `git add <文件>`、`git commit -m "说明本次改动"` 保存一个版本。

### 运行与构建

在项目目录打开 PowerShell：

```powershell
# 安装或检查便携引擎
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install.ps1

# 执行无窗口模拟测试
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run.ps1 -Mode Test

# 启动一个主机和三个客户端，验证四人联机
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\smoke-network.ps1 -Advanced

# 下载官方模板并导出 Windows 可执行文件
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run.ps1 -Mode Export

# 生成只含游戏、快速开始说明与许可的发布 ZIP
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\package.ps1

# 直接对导出的 EXE 做四进程联机验证
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\smoke-network.ps1 -Exported -Advanced

# 四人跨三关验证九种敌人、三种首领与攻击预警同步
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\smoke-network.ps1 -Exported -Biomes -Port 27861

# 英文主机与中文客户端共同游玩，验证语言设置彼此独立
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\smoke-network.ps1 -Exported -MixedLanguages -Port 27871

# 使用真实 UDP 代理注入约 100 ms 往返延迟、抖动与 2% 丢包（需 Python 3）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\smoke-network.ps1 -Clients 1 -Port 27851 -Impaired -FinishAfter 10

# 四人实际网络下，验证主机收到短/长跳与客户端预测（可附加 -Impaired）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test-network-controls-v09.ps1 -Clients 3 -Port 27924 -Impaired

# 原生 OpenGL 渲染基准，持续移动镜头；省略 --moving 则固定镜头
.\tools\runtime\Godot_v4.7.2-stable_win64_console.exe --path . --script res://tools/perf-v09.gd -- --tag=local-moving --moving
```

导出结果是 `dist/v0.9.0/SomeSide.exe`，游戏资源嵌入可执行文件。导出脚本会把引擎和字体许可一并复制到该目录，分发时保留这些许可文件；`package.ps1` 生成只含游戏、快速开始说明和许可的 0.9 ZIP。未下载模板时，第一次导出会下载约 1.28 GB 官方模板归档，仅提取 Windows x86_64 所需模板。

测试覆盖快照深拷贝、随机种子、瞄准预测、单跳与羽翼、手动拾取、多人争抢、装备冷却保留、设施交易和稀有掉落。地图可达性通过真实移动与碰撞验证：两个角色都不带道具、不冲刺，起跳和落点留出余量，并验证起跳位置偏差。压力测试继续检查四人长时间构筑与切关一致性。网络测试启动独立 Godot 进程，要求主机见到完整队伍、收到输入，客户端接收多次快照，并成功退出且没有运行时错误。证据保存在 `tools/results/network-*`。

0.9 的移动测试覆盖短/中/长按高度、不同时间步的完整跳跃轨迹、羽翼空跳、松开重按、落地、冲刺和击退；三关可达性另用显式长按命令检查。输入测试通过真实 `Input.parse_input_event` 验证 A/D 与箭头混用、键盘重复、鼠标射击/技能并用、暂停及失焦恢复。网络跳跃验收使用主机实际位置记录最高点，分别检查权威快照和客户端预测，避免把本地显示当成远端已收到的证明。

渲染基准关闭垂直同步与帧率上限，固定权威快照并停止物理、音频和网络，只比较真实原生绘制及 HUD。每场预热 120 帧、统计 360 帧，覆盖安静雨林与三关 44 敌人/160 弹丸/四角色的压力画面；另测持续移动镜头。记录包含 p50/p95、绘制调用数、GPU/CPU 时间、硬件和源码哈希。它用于比较同场景渲染成本，不代表所有电脑或完整实战都能达到同一帧率。

枪口测试覆盖八种武器、多个瞄准方向、近距离目标和出生弹丸尾迹；外观测试覆盖全部 24 种遗物、部位竞争的确定性、六槽上限、极端叠层、死亡状态和快照只读。真实图像检查继续验证左右姿态、武器模型和高叠层下的可读性。

探索调度测试额外覆盖静止、小范围巡回、原地跳跃、旧区回访、有限刷怪预算到期、闲置队友附近不刷、传送门与主动试炼，以及停留期间仍按时间增长的难度与敌人强度。地图测试验证三关拓扑差异、动态边界和设施可达性。

`-Impaired` 在主机与客户端之间放入本地 UDP 代理，对两个方向各自注入 50 ± 10 ms 延迟与 2% 丢包；报告记录实际转发、丢弃、延迟与数据量。该模式使用 Python 标准库，可与 `-Exported` 组合；正常游玩与普通网络测试不需要 Python。

`-FinishAfter 10` 让主机在测试中经真实结算发送路径结束对局，并要求所有客户端进入相同的结果界面，可验证丢包环境中的结算送达。

`-Advanced` 为四人网络验收配置四种新增武器与主动装备，逐端检查炮台、延迟陨击、团队时序增益，以及回旋、雷击和光矛投射物确实跨网络到达。自动测试模式的装备配置不影响正常开局。

`-Biomes` 在主机上依次进入三关并运行真实敌人 AI，要求每个客户端都观察到三张地图、九种普通敌人、三种首领、多个蓄力动作及圆形/直线危险区；它与 `-Advanced` 分开运行。敌人测试还验证真实伤害、走位躲避、冷却、治疗预算、眩晕和死亡取消。新渲染集成测试检查真实战斗下的快照只读、有限几何与特效预算。环境截图工具支持 `--sweep` 扫描三关全部平台边缘。

`-MixedLanguages` 为主机指定英文、客户端指定中文，并逐端检查实际显示语言；可与其他网络模式组合。开发时可用 `-- --language=en` 或 `-- --language=zh` 临时覆盖当前会话语言，不改写已保存的偏好。双语测试检查系统语言回退、保存选择、翻译完整性、英文排版、不同语言下相同的价格与玩法状态，以及金币余额显示。

这是玩法与合作架构原型。当前使用固定平台地图、完整状态快照和有限实体数量；没有持久化进行中的联机战局。局内规则、数据接口与扩展边界见 [架构说明](docs/ARCHITECTURE.md) 和 [开发接口](docs/CONTRACT.md)，本次测试、发布包哈希与验证边界见 [构建验收报告](docs/BUILD_REPORT.md)。
