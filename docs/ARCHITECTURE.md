# SomeSide 架构

SomeSide 是横版平台动作、鼠标自由瞄准、局内道具构筑与 2–4 人合作的可运行原型。代码以 Godot 4.7.2 和 GDScript 为基础；角色与怪物由精灵图绘制，其余场景和表现由程序绘制，音效由程序生成。角色能够使用射击、近战、位移和区域技能，不把战斗行为限定成发射子弹。

## 输入与瞄准

输入先变成命令：移动、跳跃、穿透平台、瞄准、主攻击、技能、冲刺和交互。持续动作与按下瞬间的动作分别处理，避免一次按键被多个模拟帧重复触发。

0.9 将 `jump` 按下边沿与 `jump_held` 持续状态分开。主动起跳后松键限制剩余上升速度，长按保持原跳跃轨迹；重新按下不会免费恢复上升力，羽翼空跳各自重新获得高度控制。方向按键由 `_input` 在 GUI 消费事件前记录，A/D 和箭头按物理键独立处理，后按方向优先、松开回退、键盘自动重复不改变优先级。暂停、页面重建与窗口失焦清理按键，网络超时也释放持续输入。

鼠标屏幕坐标通过渲染器的镜头转换为世界坐标，减去 `WeaponPose` 的固定肩点得到瞄准向量。肩点相对角色中心为 `(0, -5)`，不会在鼠标越过左右分界时突跳；肩点四像素内保留此前方向。网络上传的是归一化世界方向，而非鼠标像素坐标；因此不同分辨率、窗口大小和镜头位置不会改变另一端的攻击方向。

输入、客户端预测、权威发射与武器绘制共用 `WeaponPose`。每种武器按自己的枪管长度计算枪口，弹丸初始位置和发射事件位置都来自该点。`origin` 记录出生枪口，`travel_distance` 从零开始累计；尾迹长度不超过已经飞行的距离和插值后位置沿弹道到枪口的距离，首帧不会穿回武器。近距离碰撞使用独立的 `sweep_origin`，不移动视觉弹丸起点，也不让枪管内的敌人免疫命中。

主武器事件带 `weapon` 与玩家身份，短暂枪口反馈跟随当前绘制姿态，包括远端插值位置；死亡、离线或换装后失效。主动装备、炮台与敌人反馈保留各自原点，不绑定玩家手持武器。客户端已经预测的本地主武器反馈不会再次播放权威副本，但仍保留其他玩家、主动装备和命中反馈。

移动方向、角色面向和攻击方向可以不同。技能最终由主机消费命令，客户端不能提交“已经命中”或“造成多少伤害”。投射物、近战和范围效果都需要在权威状态内生效。

0.2 起始只有一次跳跃，额外空跳来自 `feather` 层数。地图测试使用相同的 `predict_player` 物理规则检查真实起跳、空中移动和落地；两种角色都必须在无物品、无冲刺时覆盖所有平台。起跳离边至少 32 像素，落点离边至少 24 像素，并容忍起跳位置 ±12 像素变化。

## 联机模型

合作采用玩家主机作为权威端。ENet 默认使用 UDP 27841，最多四名玩家。主机负责刷怪、随机数、伤害、击杀、货币、道具、传送门与胜负；客户端负责立即读取输入并预测自己的移动。主机定期广播状态快照，客户端根据主机确认的输入修正位置并重放尚未确认的移动命令。

本原型使用 60 Hz 模拟、20 Hz 快照与完整状态同步，便于发现规则错误、验证玩法和断线行为。快照先以 DEFLATE 压缩，再按 950 字节数据片分包发送；客户端重组后只应用更新的完整快照。终局另用可靠消息发送完整状态，避免最后一个不可靠快照丢失后无法结算。大量敌人时，完整快照的大小与序列化成本会增长；后续应先测量每秒字节数与主机帧耗时，再引入实体差量、范围裁剪或更紧凑的协议。不要将每个敌人或每枚子弹做成独立高频 RPC。

网络入口必须将连接身份和玩家 ID 绑定；收到的移动值、方向、序号和按钮需要校验。快照和事件不得携带场景节点引用。远端显示由快照与表现层完成，客户端预测不能提前扣除敌人生命、掉落装备或决定通关。

交互输入携带显示目标的 `{kind, id}`。同批输入保留第一个尚未消费的 E 目标，避免后续鼠标或位置样本改写选择。主机验证目标仍存在且在范围内；失效目标拒绝执行，不退回为另一个附近物品。`interaction_candidates` 只依赖可同步状态，返回顺序稳定的全部可选目标，`interaction_for` 返回首项。F 循环候选并记住有效的目标 ID，画面高亮、详情卡和 E 命令使用同一个 `_focus_target`；完全重叠的好坏物品也能单独选择。

远端角色、敌人和投射物在表现层插值；本地玩家使用预测与误差平滑。插值不修改模拟快照，换关和新局时清理旧实体缓存。广播只发给 ENet 仍处于已连接状态的节点，避免同时退出的客户端触发无效通道发送。

固定种子用于主机复现与测试，并不意味着要使用确定性锁步。主机退出后房间结束；当前没有主机迁移、公共匹配服务、账号系统、NAT 穿透或跨互联网延迟补偿服务。

## 战斗与构筑

静态角色、道具目录提供 ID、名称、说明和表现颜色；角色实例保存当前生命、技能冷却、无敌时间和道具层数。快照必须深拷贝，避免渲染器、客户端或测试修改权威世界的嵌套对象。

`items` 只存可叠加被动。`weapon` 与 `equipment` 各存一个可替换槽位 ID；普通攻击和主动效果按当前装备 ID 执行，不再绑定角色种类。物品替换在一个权威步骤中完成：校验目标、消费地面实体、换槽、把旧装备及剩余冷却放回地面。交换取当前冷却与被拾取装备冷却的较大值并应用短暂装备锁，避免刷新技能。

金币与治疗可自动收集，其他战利品必须由明确的 E 输入授予。普通/精英死亡分别以 3% / 8% 概率尝试掉物，首领两件保证掉落；同一死亡不能重复结算。设施产出地面奖励，不直接塞进背包。三选终端共享锁组，生命祭坛记录非致死生命代价，战斗信标只追踪自己生成的敌人；环境怪物不会误算为该挑战的未完成目标。

设施借鉴《雨中冒险 2》交互物的空间呈现和代价分类，不照搬其概率与数值。SomeSide 的目录、奖励规则、风险提示和联机事务是独立实现。

0.5 目录包含 24 被动、8 武器、8 主动装备，共 40 件，`Content` 提供统一的稀有度名称、顺序和颜色。普通奖励先按 88/7/5 分类别，再按来源和关卡选择稀有度；抽出的装备排除初始、穿戴、地面和未开设施预留 ID。近期历史只作软排除，池耗尽时使用硬可用池中最久未出的候选，避免历史把装备永久封锁；硬排除不放宽。历史进入快照且使用主机随机数，固定种子可复现。

新增炮台位于 `state.deployables`，延迟陨击位于 `state.effects`，中毒、减速、护盾、时序等计时器属于权威实体状态；客户端只展示，不能从事件再执行伤害。持有遗物以最多 24 个常驻小图标展示，悬停详情期间 E 不会误拾地面物品。Tab 默认展示实际构筑，另外三类筛选可查看完整目录。

攻击产生短时事件，供音效与渲染器消费。生命扣除和死亡只发生于模拟。道具组合需要有明确的叠加规则，并对连锁效果、投射物数量、敌人数量和事件数量设置上限。上限服务于实际性能和可读性；优化优先级由实测决定。

0.4 的攻击事件与投射物携带 `visual_stacks` 和 `visual_strength`，让客户端按道具叠层强化局部光效。表现层对粒子、伤害数字和震动设硬上限，特效强度与震动开关可由用户设置；这些值不会参与伤害计算。M 地图按当前 `world_size` 缩放实际平台、地标、设施和玩家，合作时打开个人地图不会暂停其他人。

0.6 的 `PlayerAppearance.build(items, dead)` 只读取遗物层数，输出最多六个部位的饰件描述，不写回物品或玩家快照。所有 24 个被动都有对应饰件；同部位按稀有度、层数和固定顺序选取，尺寸与亮度均封顶。世界绘制按面向镜像附着点，武器继续独立随瞄准旋转；死亡时不显示饰件。合作端从已有 `items` 状态重建同一结果，无需新增饰件网络状态。

地图由平台、宝箱、出生点和传送门构成，每关具有独立尺寸与布局。0.4 的普通敌人仍跟随新区域探索产生有限波次，局部来回或原地跳跃不积累刷怪预算。难度改为由实际 `state.time` 推进，包括闲置时间；它提高新敌人的生命和敌人攻击伤害，不给既有敌人回满生命。每个玩家记录探索锚点、已探索地点、窗口和剩余预算；只有活跃探索者可成为普通刷怪的位置来源。传送门和主动试炼保留明确的事件压力。合作中一个角色倒下不会立即结束游戏，队友可以救援；全部倒下则失败。

## 关卡敌人和危险预警

0.7 的敌人定义与刷怪策略分离：`EnemyCatalog` 提供本关池、飞行替补和首领参数，探索、信标与传送门均从该池取样。AI 保存 `attack_kind`、`attack_target`、`attack_dir`、`telegraph` 与 `telegraph_max`，在蓄力开始时锁定位置与方向。闪现后的齐射使用第二段明确蓄力；射线单位从预警到生效期间固定发射位置，地面哨卫落地后才能开始射线。

延迟圆形与直线攻击记录于权威 `state.hazards`，上限 24。危险区保存施法者、位置、方向、长度/半径、倒计时和已命中的玩家 ID；警告阶段无伤害，生效后每个玩家至多命中一次，眩晕、施法者死亡或切关会清除。客户端只根据同一几何绘制预警，不根据特效事件执行伤害。敌方射击事件与弹丸共用出生点，并携带敌人身份和关卡元数据。

环境与实体绘制只使用现有碰撞几何，装饰不改变可达性。玩家继续复用 `WeaponPose` 与六部位遗物饰件；小尺寸装甲分层和敌我弹形承担主要辨识度。危险区最后绘制，防止被植被、实体或普通特效完全覆盖；渲染仍遵守原有粒子、数字和震动上限。

0.9 缓存重复的绘制工作。普通平台静态材质和静态地标使用原生 SubViewport 纹理，最多 40 项、48 MiB 颜色纹理预算，按使用时间淘汰；每帧最多创建两项，布局 hash 变化时清理旧资源。底层地板保留按镜头深度的原绘制，蕨叶、水流及旋转地标继续动态更新；移动时背景直接绘制，停驻时可复用。该预算是颜色纹理估算，驱动实际显存可包含额外缓冲。

`sprite_atlas.gd` 在世界节点首次进入场景（菜单期）预热普通敌人和敌方弹丸，普通怪采用 16 个动画相位，含精英、受击和冲锋准备姿态；Boss 与玩家保持原动态绘制。图集颜色纹理总预算 32 MiB，当前实际计划 28.8125 MiB，本机 OpenGL texture monitor 增量约 57.625 MiB。图集由所属世界节点管理，切关不重复生成，释放世界时随之释放；headless 不创建 GPU 图集。友方弹芯、尾迹与危险预警仍按当前状态绘制，尾迹继续遵守出生点与飞行距离限制。

内容目录按 ID 建索引，返回调用方独立的字典副本，避免每次射击或查看物品重建 40 条记录。交互面板只在内容、可支付性、风险、装备、候选顺序、语言或详情状态改变时更新样式与布局；目标距离和面板位置仍实时更新。金币余额未变化时不重复量字或重设尺寸。

## 显示语言与金币

0.10 的角色与怪物身体通过 `assets/sprites/actors.json` 描述纹理、逐帧裁剪、中心锚点、缩放和动画序列。两名角色各有待机、跑步和空中姿态，九种普通敌人与三种首领各有四帧。`SidePixelActorRenderer` 校验裁剪边界和内存预算，复用三张源纹理。0.11 将每种角色的所有帧预先采样到共用尺寸、整数锚点的逻辑像素图集，避免大原图在运动时反复缩小采样；只为精灵使用最近邻，并在实际窗口拉伸后的物理像素空间对齐显示位置。源图保持不变，新增缓存有独立 8 MiB 上限。

帧选择只读取已有速度、地面状态、蓄力与受击状态；素材、动画帧号不进入权威快照。精灵只替换身体层，鼠标瞄准武器和六槽遗物饰件仍独立绘制，枪口、碰撞体和基础移动不变。像素身体不再叠加与动画独立的连续上下浮动。缺失某项素材时回退既有矢量身体；完整像素素材可用时省去普通敌人的矢量图集预烘。

0.11 对本机和主机的固定步长位置保存前后显示样本，让角色、镜头、枪口和弹丸共用一致的插值位置，避免 60 Hz 角色阶跃与高刷新率平滑镜头产生反向抖动。插值不越过已知物理位置，显示延迟最多一个物理步；低于物理频率时也保持一致的显示延迟。客户端本地角色以预测 tick 为采样时钟，远端继续使用原网络插值，避免叠加两次平滑。换关、时间回退、大幅传送和生死状态改变清理或重置样本。新鲜主武器弹丸在显示层从显示枪口接入，权威出生点和碰撞数据保持不变。

新版粒子按武器区分枪口形状，按命中方向发散碎屑，并为生物、岩石与机械死亡选择材质颜色。火花、碎片、余烬和低透明烟雾使用速度、阻力与重力的短生命周期运动，并按四档线宽批量绘制；屏外粒子不提交几何。总效果仍不超过 384 个，保留 64 个槽位给枪口、刀弧和冲击等较大轮廓。伤害数字最多 32 个，震动幅度最多五像素，危险预警最后绘制以保证可读性。

FPS 是 `Engine.get_frames_per_second()` 的实际渲染帧率，与 60 Hz 模拟步进分开。常驻标签每 0.25 秒刷新，跨菜单重建保留，忽略鼠标事件；默认开启，F3 和设置按钮共用 `profile.show_fps`。背包和地图把读数移到顶部留白，退出后恢复金币下方。现有自动验收与命令行语言覆盖仍禁止写入真实用户偏好。

0.11 的菜单、选角、大厅、设置、指南、暂停、结算、背包和地图共享暗青面板、细边框、暖金主动作及明确的键盘焦点样式。通用页面显示游戏名、页面标题和简短说明，底部只保留版本号；角色卡使用真实精灵，房间成员按姓名、角色与准备状态分栏，结算采用区域/时间/击杀统计卡。所有文案经过本地语言层，UI 重建仍沿用原回调与保存边界。

0.8 的 `SideLocale` 只负责本地显示。中文原文作为精确字典键，物品 ID、数值、玩家昵称和权威状态不参与文本替换；格式化文案先翻译模板，再插入参数。首次运行使用系统 locale，`zh` 及其区域变体选择简体中文，其余语言回退英文，保存的有效偏好优先。命令行语言覆盖仅作用于当前会话。

交互检查生成的临时记录按本地语言显示，事务仍只提交和验证 `kind/id`。服务器通知发送原始 `message_key` 与 `message_args`，客户端自行翻译；两种语言的玩家可以处于同一局。世界绘制在显示首领、地图地标等文字时翻译，快照中的目录与名称保持原样。大号金币余额来自当前玩家的实际 `coins`，不会因为格式或语言变化而影响价格、共享收益或交易。

## 本地开发与验证

Godot 编辑器、导出模板和编辑器数据都放在 `tools/runtime`。`_sc_` 开启编辑器自包含模式；无需写入 PATH、安装系统服务或替换已有引擎。首次下载以官方发布中的 `SHA512-SUMS.txt` 验证归档。`tools/.gdignore` 阻止编辑器扫描下载缓存。

模拟测试通过 `tools/run.ps1 -Mode Test` 执行，覆盖随机种子复现、嵌套快照隔离、自由瞄准、客户端移动预测、购买扣费与合作胜负。联机测试需使用独立主机和客户端进程，检查真正的 ENet 连接、状态接收与正常退出。Windows 导出使用官方 release 模板并把游戏数据嵌入可执行文件。

这是为可玩原型服务的分层结构。添加角色或道具时先延续现有数据与模拟边界；没有需要时不引入通用 ECS、技能编辑器、数据库、微服务或插件框架。
