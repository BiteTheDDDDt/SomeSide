# SomeSide 0.10.0 构建验收报告

验证日期：2026-10-05。引擎：Godot 4.7.2 stable / Windows x64 / OpenGL Compatibility。上一版性能、跳跃和输入修复的完整记录保留在 `BUILD_REPORT_v0.9.0.md`，Git 标签 `v0.9.0`。

## 本次交付

- 默认在金币下方显示实际 FPS；F3 与设置按钮切换，偏好保存，中英文设置一致。读数来自 Engine，每 0.25 秒刷新；与固定 60 Hz 物理无关。
- 两名角色、九种普通怪物、三种 Boss 接入三张生成的 RGBA 精灵表。角色各六帧，敌人和 Boss 各四帧；运行时按待机、移动、空中、蓄力及攻击状态选帧。明确逐帧裁剪与共同躯干锚点，最近邻采样只作用于精灵纹理。
- 独立武器、鼠标瞄准、实际枪口、遗物饰件、受击闪光、精英标记和危险预警继续保留；碰撞体、地图可达性、移动与伤害逻辑没有改变。
- 八种武器有不同的发射反馈；命中方向飞溅、碎片、余烬、烟雾和冲击环分层显示。死亡碎片按生物、岩石和机械材质区分。最多 384 特效、32 伤害数字、五像素震动；小粒子与碎裂线段最多四批绘制，危险预警最后绘制。

素材通过内置 imagegen 工具生成，完整提示词与原始输出位置说明见 `assets/sprites/ART_PROMPTS.md`；项目内为 `heroes-v1.png`、`enemies-v1.png`、`bosses-v1.png`。PNG 未经程序改绘，透明通道保留。`actors.json` 只定义裁剪、锚点与动画。三纹理 RGBA 尺寸成本 18,872,976 bytes（约 18 MiB），上限 64 MiB；全部像素角色可用时不再预烘普通敌人矢量图集，缺失项仍有回退。

- 目视检查实际武器/饰件组合、两角色六姿态、九种怪物和三 Boss 四帧、三种死亡材质、八武器反馈、中英设置和十位金币余额。截图位于 `pixel-actors-v010-*.png`、`v010-fx-{weapons,battle,materials}.png`、`v010-fps-*.png`。

- 最终 EXE 四进程 ENet：英文主机与三个中文客户端共同经过三关，观察到九种普通敌人、三种首领和攻击预警。四端退出码为 0，全部通过并均加载 14 actors / 3 textures / 0 errors。证据：`network-export-biomes-bilingual-20261005-005724/summary.json`。这是真实本机多进程网络验收，未声明公共互联网联机已测。
- FPS 测试断言真实用户配置文件未改变；自动化与临时语言覆盖继续使用既有保存保护。

## 性能

硬件：NVIDIA GeForce RTX 5070 Ti Laptop GPU，1280×720，关闭垂直同步与帧率上限；固定模拟快照，关闭物理、网络和音频。每场预热 120 帧、统计 360 帧。压力画面包括四名角色、44 敌人、160 弹丸、24 掉落物及六个危险区。测量为原生画面与 HUD 的成本，不能等同完整实战 FPS。

| 场景 | 固定镜头 p50 / p95 ms | 移动镜头 p50 / p95 ms |
| --- | --- | --- |
| 安静雨林 | 5.252 / 9.492 | 7.914 / 10.038 |
| 密集雨林 | 17.559 / 20.229 | 19.497 / 21.875 |
| 密集峡谷 | 13.074 / 15.636 | 14.672 / 17.816 |
| 密集遗迹 | 15.406 / 18.231 | 18.007 / 21.212 |

相对本机 v0.9 已记录的同场景移动镜头基准，三处密集画面 p50 从 27.502 / 21.956 / 25.453 ms 降到 19.497 / 14.672 / 18.007 ms。仍有密集场景超过 16.67 ms，因此不宣称所有战斗稳定 60 FPS。证据：`perf-v10-final.json`、`perf-v10-final-moving.json`（包含源码哈希、硬件、CPU/GPU 时间与缓存预算），日志 stderr 为空。

另以同一进程、相同角色模块和持续密集事件，仅切换 v0.9/v0.10 特效进行对照。最终合批版本：FX 绘制 CPU p50 3.981→3.007 ms，整帧 p50 22.194→20.202 ms，p95 27.102→24.898 ms，绘制调用中位数 1802→1636。此组使用当时相同的矢量角色模块以隔离特效变化，不能和最终像素场景数字混用。证据：`v010-fx-performance-reverse.json`。首次试验因碎裂环未合批而存在尾帧增加，最终版本修复后反序复核。
